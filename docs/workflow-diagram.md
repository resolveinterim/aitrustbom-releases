# Workflow diagram

This diagram shows the pull-request flow described in [How you use AI TrustBOM](workflow.md), with the status the pull-request comment shows at each point and the loops back when gaps remain or Trust requests changes.

<p align="center"><img src="images/workflow.svg" alt="Workflow diagram. Set up once with trustbom init. A developer opens a pull request that adds or changes AI; the check fails and the comment says Not approved, Needs information, listing what changed, what is missing and whether trust/card.json is out of date. The developer fills the gaps in trust/manual.yml, then scans, commits and pushes until the comment says Ready for sign-off. The developer runs trustbom propose, commits and pushes; the first sign-off adds Trust's two decisions. The check passes and the comment says Proposed, not approved. Trust, who is not the author, reviews and merges; changes requested go back to filling the gaps. Optionally, trustbom github-rules apply makes GitHub block the merge until a code owner other than the author approves. The default branch then holds the Approved version, which the paid export, answer and publish commands share; export --draft is free and watermarked. The customer checks the pack with the free trustbom verify. The next AI change starts again at the pull request, and the comment says Not approved (stale) until Trust signs it off again." width="75%"></p>
